# Welcome to FLP

Free Law Project is a non-profit that provides free, public access to legal data. We build and maintain open-source tools that make the legal system more transparent and accessible — used by self-represented litigants, journalists, researchers, and legal professionals.

Glad you're here. This repo gets you from a fresh machine to your first merged change.

## Start here

**[Day One](day-one.md)** — a numbered path where every step has a pass condition, ending at your first open pull request. Half a day is a realistic target.

Then:

- **[Git Setup](git-setup.md)** — SSH keys, global git config, and hooks. Step 2 of the day-one path, and the one-time setup you'll be glad you did properly.
- **[Culture](culture.md)** — async-first communication, the GitHub paper trail, urgency tiers, Work → Right → Fast. Day-two reading.

## Hour zero: request access

These are the only items gated on another human, so send them before you read anything else. One batched message to your manager or onboarding buddy:

- **GitHub** — invite to the [freelawproject org](https://github.com/freelawproject) and your project's team
- **Slack** — workspace invite
- **Google Workspace** — your `@free.law` account
- **Password manager** — vault access
- **Claude Code** — a seat on the FLP team plan
- **Project credentials** — anything your repo needs that isn't public

Everything else on the day-one path is self-serve, so fire these off and keep going while you wait.

## What lives elsewhere

- **Project setup** — dependency install, services, environment variables, database seeding: each repo's README and wiki. Those are maintained by the people in that code daily, so they're the source of truth over anything here.
- **Team mechanics** — board columns, sprint cadence, branch-name shape, deploy flow. These vary by team; your team's repo docs and your onboarding buddy cover them.
- **HR policies** — the [HR repo](https://github.com/freelawproject/hr): handbook, time off, benefits, parental leave.

## Archive

The [`archive/`](archive/) directory holds the previous topic-organized docs (dev environment, git workflow, coding standards, AI-assisted dev, projects, resources). **They're superseded and unmaintained — some content is known to be stale, so don't treat any of it as current.** They're kept only as raw material while the day-one path settles, and the directory gets deleted once it has.
